# ADH Daemon (daemon/src/) — MAP

ADH Daemon / `adhd` (Node 24 + TypeScript, runs `.ts` directly, no build step). HTTP/WS `8088`, agent TCP `8761`. App pin: `GET /<package>` and `POST /<package>/mcp`.

## Module layout (post-split)

| `config.ts` | **Process configuration.** ADH port env vars plus Host LAN/local Web UI URL discovery. | node only |

| `sandbox_fs.ts` | **App sandbox listing without a live process.** `listSandboxDir` / `readSandboxFile` read `/data/data/<package>` (and the `/data/user/<id>/` path it resolves to) through `adb` + `su`. | `service.ts` | **Service layer.** Agent-command transport (`sendCmd`/`agentCmd`/`pickSid`), dump engine (`readMem`/`reconstructSo`/`repairDexHeader`/`dumpRegion`/`dumpBuf`/`dumpBufPath`/`modulesFromMaps`/`dumpAppSo`), capture ops (`setCapture` — the one implementation behind the `capture_start`/`capture_stop` tools: install + a derived `installed===expected` verdict, and stop-that-drains-first —/`startCaptureLoop`/`dumpAllDex` — which now classifies every dex (carrier vs real code) and indexes it in the same pass —/`autoDumpDex`/`applyCaptureEnabled`), artifact retention (`pruneArtifactsAndIndex` — wires the eviction plan to the dex-index row). `capSeq` is service-local (`++`'d in `startCaptureLoop` — can't reassign an imported binding in ESM). **Memory write + undo:** `writeMem` validates the hex/address before sending (a bad request writes nothing), calls the agent's `write`, and remembers the returned `before` bytes per session (bounded, 64 entries); `restoreMem` puts them back and `listWriteUndo` lists what is still restorable — so an operator/AI patches one branch and undoes it with one call, without tracking bytes. `moduleLoads(sid)` decodes the MODULE_LOAD capture records back into `{path,handle,base,size}` so a caller never hex-decodes a capture by hand. **Startup pre-arm:** `applyStartupHooks(sid)` runs on hello (index.ts) BEFORE the capture loop — `autoAntiDebugEnabled` (settings + `ADH_AUTO_ANTIDEBUG` override) and `shouldPreArm(pkg)` (settings.startup.packages whitelist, empty = all) decide whether to install the minimal plan, then `session.startupHooks` carries the hookIds so they are visible and undoable. Those two are installed LATER by `startupWidenPlan` / `widenStartupHooks` (`startup.widenAfterMs` + `widenTargets`, unref'd timer, once per session) so the app is settled first — verified on device: at hello 1 hook and `access` → ENOENT, 5 s later 3 hooks and `access` → EACCES, process alive. `daemon/test/agent_caps.test.ts` guards the agent capability manifest against the dispatch chain. **`withCaptureSuspended` was removed on 2026-10-01** together with the one-shot probe routes it existed for: it stopped/restarted the persistent hooks so a probe saw a clean GOT slot, and the last probe that needed that (`file_hook_test`) is gone — reintroduce it deliberately if a future call-site tool needs a clean slot, not by accident. | `state.ts`, `dex.ts`, `so_select.ts`, node |
| `mcp.ts` | **MCP Server (JSON-RPC).** `MCP_TOOLS` registry (single array — **add a tool = add one entry**) + `handleMcp`. AI-first tools: `capabilities` answers with the agent's own hello `caps` (ops + limits) plus the daemon body cap, so a client plans from the running build instead of a document; `memory_write` / `memory_restore` are the write side of `memory_read` with host-kept undo; `module_watch` arms/disarms the MODULE_LOAD broadcast and lists the records; `recipe` runs a named multi-step workflow from `recipes.ts` (one call instead of eight in the right order); `settings` gets/patches the daemon settings (including the `startup` pre-arm policy) so an AI can configure the daemon without dropping to REST. All of them are shared with the REST routes, never a second implementation. Handlers delegate to `service.ts` primitives + `state.ts` reads + DEX/index/analysis layers. | `state.ts`, `service.ts`, `dex.ts`, `dex_index.ts`, `analysis.ts`, `memory.ts`, `syscall_watch.ts`, `recipes.ts` |
| `recipes.ts` | **Named multi-step workflows.** The primitives answer "what CAN I do"; a recipe answers "do the thing": `triage` (caps, maps, dex files, a capture window with module-load watch, detection summary, capture counts), `capture_window` (arm capture, optionally run ONE caller-supplied Java method as the trigger, wait, digest), `http_capture` (arm TLS, optionally trigger, drain, pair plaintext into whole HTTP exchanges), `anti_debug` (plan without `confirm:true`; with it, neutralizes ptrace/access/faccessat return+errno and returns the hookIds, `undoHookIds` removes a previous run), `unpack` (cold start + every dex into a bundle). Every step reports `ok`/`ms`/`error` and a failed step does not abort the rest, so a partial answer stays usable; steps return small summaries, never raw agent replies. Recipes orchestrate only — no new agent capability is invented here. Unit-tested (`test/recipes.test.ts`). | `state.ts`, `service.ts`, `detect.ts`, `http_exchange.ts` |

| `cli.ts` | **`adh` CLI — the operator's command line, and a CLIENT only.** `doctor` (daemon health + flashed-agent-vs-source version pairing + backends), `target` (resolve ONE agent and report its live facts), `unpack` (one-shot `dump_all_dex` + per-dex classification + optional save). ## Why the split (was: one 1585-line `index.ts`)

Adding a crypto hook once meant reading the whole file; the REST surface was inline `if(pathname===)` blocks. State, service, MCP, and the three HTTP route domains are now separate, while `router.ts` preserves one ordered table and one matching implementation.

## Adding a new capability

- **MCP tool**: add one `{ name, description, inputSchema, handler }` to `MCP_TOOLS` in `mcp.ts`. Handler calls `agentCmd`/`dumpBuf`/`dumpRegion`/… from `service.ts`. Done — `tools/list` + `tools/call` pick it up automatically.
- **REST route**: add one table entry to the owning `http/routes_*.ts` domain. Preserve domain composition order in `http/router.ts` when paths overlap.
- **Agent command op**: handled in the agent C `command_loop` (Phase 3 — table-driven after refactor).
- **CLI subcommand**: add one entry to `COMMANDS` in `cli.ts` (its own flags + `handlerFlags`). Two guards
  then apply automatically: `test/cli_args.test.ts` fails if a declared flag is not in `handlerFlags`, and
  `tools/verify_v100_adh_cli.sh` fails unless every declared flag has an observable effect. Never add a
  flag to the shared set "for later" — an accepted-but-ignored flag is how this kind of tool lies.

## Known flake (pre-existing, in `service.ts` reconstructSo path)

`verify_v08_disasm`/`verify_v08_analyze` intermittently report `exports=0` on the memory-reconstructed `.so`: `readMem` breaks early on a short first chunk (`service.ts` `readMem`), truncating a PT_LOAD and dropping the dynamic segment. Passes on re-run. Fix candidate: read each PT_LOAD segment boundary precisely rather than assuming contiguous.

### backends.ts (module W)

Shared injection-backend matrix: `backendMatrix()` (sessions by entry + Zygisk pointers) and `classifySession()` (zygisk / self_load from the agent's maps). Frida Gadget is not advertised. Used by REST `GET /api/backends` and MCP `backends`.
