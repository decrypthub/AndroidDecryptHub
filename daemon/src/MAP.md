# ADH Daemon (daemon/src/) — MAP

ADH Daemon / `adhd` (Node 24 + TypeScript, runs `.ts` directly, no build step). HTTP/WS `8088`, agent TCP `8761`. App pin: `GET /<package>` and `POST /<package>/mcp`.

## Module layout (post-split)

| File | Role | Imports |
|---|---|---|
| `config.ts` | **Process configuration.** ADH port env vars plus Host LAN/local Web UI URL discovery. | node only |
| `state.ts` | **Shared state + leaf helpers.** All registries (`sessions`/`dumps`/`agentSockets`/`pending`), `events`+`recordEvent`, `settings`+`mergeSettings`/`saveSettings`/`configStats`, capture store (`captures`/`captureTimers`/`capStats`/`captureHealth`), **on-disk artifact store** (`loadArtifactsFromDisk` adopts `captures/` into the `dumps` map at boot, `pruneArtifacts` enforces `settings.artifacts`, `artifactStats`), classification (`hexToPreview`/`categoryOf`/`classify`/`cryptoIdentify`), `captureModules` (reads settings, not a target constant), infra (`wss`/`broadcast`/`log`/`readBody`), framing (`frameJson`/`FRAME_JSON`/`FRAME_MAX`). **Imports nothing from service/mcp/index** (no cycles). | node + ws only |
| `service.ts` | **Service layer.** Agent-command transport (`sendCmd`/`agentCmd`/`pickSid`), dump engine (`readMem`/`reconstructSo`/`repairDexHeader`/`dumpRegion`/`dumpBuf`/`dumpBufPath`/`modulesFromMaps`), capture ops (`setCapture` — the one implementation behind the `capture_start`/`capture_stop` tools: install + a derived `installed===expected` verdict, and stop-that-drains-first —/`startCaptureLoop`/`dumpAllDex` — which now classifies every dex (carrier vs real code) and indexes it in the same pass —/`autoDumpDex`/`applyCaptureEnabled`), artifact retention (`pruneArtifactsAndIndex` — wires the eviction plan to the dex-index row). `capSeq` is service-local (`++`'d in `startCaptureLoop` — can't reassign an imported binding in ESM). **`withCaptureSuspended` was removed on 2026-10-01** together with the one-shot probe routes it existed for: it stopped/restarted the persistent hooks so a probe saw a clean GOT slot, and the last probe that needed that (`file_hook_test`) is gone — reintroduce it deliberately if a future call-site tool needs a clean slot, not by accident. | `state.ts`, `dex.ts`, node |
| `mcp.ts` | **MCP Server (JSON-RPC).** `MCP_TOOLS` registry (single array — **add a tool = add one entry**) + `handleMcp`. Handlers delegate to `service.ts` primitives + `state.ts` reads + DEX/index/analysis layers. | `state.ts`, `service.ts`, `dex.ts`, `dex_index.ts`, `analysis.ts`, `memory.ts`, `syscall_watch.ts` |
| `http/router.ts` | **REST composition and first-match dispatch.** Creates request context, concatenates route domains in stable order, then `/<package>` dashboard + `POST /<package>/mcp` pin, then 404. | `http/routes_*.ts`, `mcp.ts` |
| `http/routes_system.ts` | Health, MCP, captures/events, settings, destructive data lifecycle, diagnostics, agent registry, `/wechat-follow.png`, `/raven.svg`/`/raven.png`/`/favicon.ico`, and `/api/mcp/config` (direct HTTP MCP endpoint metadata) | `config.ts`, `state.ts`, `service.ts`, `mcp.ts` | — also serves `GET /api/backends` (injection-backend matrix: sessions by entry + host-side Frida Gadget cache; read-only, the daemon has no adb).
| `http/routes_runtime.ts` | Live agent execution routes: maps, object/JNI/ART, hook/trace, filesystem, memory, trigger, and unpack commands. | `state.ts`, `service.ts`, `memory.ts`, `syscall_watch.ts` |
| `http/routes_analysis.ts` | Host native/DEX analysis, module reconstruction, dump download, and dashboard routes. | `state.ts`, `service.ts`, `dex.ts`, `dex_index.ts`, `analysis.ts` |
| `index.ts` | **Boot + agent-TCP frame decode only.** Owns `agentServer`/`httpServer`/WS upgrade/listen/SIGINT and delegates HTTP requests to `http/router.ts`. | `config.ts`, `state.ts`, `service.ts`, `http/router.ts` |
| `cli.ts` | **`adh` CLI — the operator's command line, and a CLIENT only.** `doctor` (daemon health + flashed-agent-vs-source version pairing + backends), `target` (resolve ONE agent and report its live facts), `unpack` (one-shot `dump_all_dex` + per-dex classification + optional save). Every subcommand is HTTP against `adhd`, so it works against a remote daemon; it imports **only `config.ts`** and nothing imports it. It exists because the "find the online agent for a package and pick its session" block had been hand-copied into 76 `tools/verify_*.sh` scripts and re-derived in every investigation — that block now has one implementation. Flags are declared **per command**, an unknown/misplaced one is a usage error, and both `test/cli_args.test.ts` (declared ⇒ consumed) and `tools/verify_v100_adh_cli.sh` (declared ⇒ observable effect) fail if a flag is accepted and ignored. Exit codes reuse the gate's three states: `0 ok / 1 fail / 2 usage / 3 unavailable` (= SKIP). | `config.ts` |
| `artifacts.ts` | **Pure artifact-store policy** (no state, no fs): `artifactKindOf` maps an on-disk filename to its kind, `planArtifactEviction` decides what to reclaim (over-age first, then oldest-first to the byte budget; `protectSha` spares the artifact just written; an unreadable mtime is kept, not assumed ancient). Unit-tested directly — `state.ts` owns the store, this owns the decisions. | — |
| `flow.ts` | **Network↔crypto correlation.** The join used to be computed inline in the `/api/flow/watch` handler next to a one-shot agent op that hardcoded the target's `run()` trigger; both are gone (2026-10-01) and the join moved here: pure `correlateFlow(records)` (same thread + `WINDOW_NS` window, `asciiOf` shaping for both sides, an explicit `reason` when the result is empty and a `caveat` on every reply saying this is co-occurrence, NOT the deterministic content-hash join WS-I still owes), plus the thin `flowCorrelate(session)` shell that reads the capture store and attaches `storeLossNote`. Backs the MCP tool `flow_correlate`. Unit-tested (`test/flow.test.ts`), including a cross-thread negative case and the window boundary. | `state.ts` (reads) |
| `dex.ts` | Pure DEX parser/rebuilder plus proto/field/code analysis (`parseDex`/`analyzeDexCode`/`searchDex`/`extractMethodCode`/`invokeXref`/`cryptoScan`/`analyzeCoverage`/`rebuildStandardDex`/`recoverFromSnapshots`/`stripMethodCode`). No daemon state. | — |
| `dex_index.ts` | WS-F persistent SQLite index keyed by DEX SHA/size/parser version: strings and callers, fields and read/write sites, methods, call edges, and `Class.forName` targets. | `state.ts`, `dex.ts`, node:sqlite |
| `analysis.ts` | Host-side ELF analysis shelling out to NDK llvm tools (`analyzeSo`/`cryptoConstScan`/`svcScan`/`disasmSo`/`OBJDUMP`). Also exports `CRYPTO_CONSTS` (the standard constant table) so `crypto_variants.ts` reuses one copy instead of keeping a second. | — |
| `crypto_variants.ts` | **Structural crypto identification** (`scanCryptoVariants`), the answer to "the app changed the algorithm". `cryptoConstScan` looks for the STANDARD bytes of a standard algorithm, so a target that implements MD5/base64/CRC itself and perturbs it matches nothing — and the runtime capture path (which names a capture after the library function called) sees nothing either, i.e. both layers go blind at once. This module keys on the parts a mutation leaves intact (MD5: the K table anchors while the IV is rewritten; SHA1: the opposite, the IV anchors while the round constants are rewritten), reports `standard` vs `variant` **with the missing companion as evidence**, finds base64 alphabets by SHAPE (64 distinct chars from the vocabulary, isolated) and counts the substitution drift, and states its own blind spots in `limits` (runtime-generated tables; a mutation that rewrites the anchor too). Verified against compiled fixtures carrying the mutations a reference sample repo actually ships — see `tools/verify_v101_crypto_variants.sh`. Pure: no state, no fs. | — |
| `capstone.ts` | Pure host-side raw-byte AArch64 disassembly through Capstone 5 (WASM); no daemon state. | `capstone-wasm` |
| `memory.ts` | Live memory helpers combining agent `read` with host-side Capstone (`liveDisasm`, module+offset resolution). | `service.ts`, `capstone.ts` |
| `native_hook_all.ts` | Batch native hooking by exported-symbol pattern: parses the module dump with `parseDynSymbols`, filters exported FUNCTIONS by prefix/contains/exact (deterministic address order, optional exclude), installs inline hooks up to the 16-slot ceiling and reports matched vs installed plus per-symbol failures; `nativeUnhookAll` removes exactly the given ids. Pure `selectExportSymbols` is unit-tested. | `service.ts`, `module_symbols.ts`, `backtrace.ts` |
| `java_trace.ts` | Class-level Java tracing in three phases (start = hook_all and keep the hooks, digest = drain + group JAVA_HOOK events per method with a timeline and caller histogram, stop = unhook exactly those ids). Pure `digestJavaTrace` is unit-tested. | `state.ts`, `service.ts` |
| `syscall_trace.ts` | Three-phase syscall tracing (start = syscall_watch + build the `expected {hookId: nr}` map from its response, digest = shared-drain + syscall_digest, stop = unhook exactly those ids). Keeps the attribution honest end to end and never does an implicit unhook-all. `syscall_trace.test.ts` covers the assembly with injected deps. | `syscall_watch.ts`, `syscall_digest.ts`, `native_hook_all.ts` |
| `syscall_digest.ts` | Groups watched syscall hits (NATIVE_HOOK events with x8 + the at-hit caller chain) by (syscall number, first caller frame outside libc) with counts/window/tids, and reports runtime-vs-attributed x8 mismatches. Pure `digestSyscallSamples` is unit-tested; `syscallDigest()` reads the capture store and symbolizes the caller frames. | `state.ts`, `module_symbols.ts` |
| `trace_digest.ts` | Turns a QBDI instruction stream into an analyst-readable digest (pure `digestTrace`: loops by back-edge target, call targets, memory access shapes, materialised constants with crypto magics flagged, branch shape, hottest instructions) and `traceDigest()` runs `qbdi_trace` + symbolizes call targets and hot addresses through `module_symbols.ts`. Unit-tested without a device. | `service.ts`, `module_symbols.ts` |
| `module_symbols.ts` | Shared address -> module + dynamic symbol resolution (maps region containment, PT_DYNAMIC dynsym, archive-mapped detection) used by `backtrace.ts` and `trace_digest.ts`. | `service.ts`, `backtrace.ts` |
| `backtrace.ts` | Hook-hit caller backtrace: prefers the at-hit chain the agent captured (x30 + the x29 walk, opt-in per hook via `native_hook backtrace:true`) and falls back to a live x29 walk for explicit fp/lr. Resolves each frame by its containing maps region (min/max path matching mis-attributed sandbox frames to base.apk) and symbolizes through PT_DYNAMIC (`parseDynSymbols`/`symbolize`, works on memory reconstructions where the section table is gone). Honest stops: unmapped return address, unreadable stack, fp outside a writable mapping, non-ascending chain; archive-mapped libs report `symbolSource=archive-mapped` instead of guessing names. | `state.ts`, `service.ts` |
| `syscall_watch.ts` | Host-orchestrated `svc #0` watch: reconstruct module + `svcScan` + per-site **static attribution** (`attributeSite` decodes the MOV that materialises x8; note JS bitwise AND is signed, so every masked compare is `>>> 0`) + name/number filtering + per-site `native_hook`; events carry x8 as the runtime syscall number. `libc.so` is the main target since app code reaches the kernel through its stubs. Also exports `parseSyscallToken`/`syscallName` for `native_syscall_scan` and the unit test. | `service.ts`, `analysis.ts` |
**Import graph is one-directional**: `state ← service ← mcp/http/index`; `dex_index` depends only on `state` + pure `dex`; `service` also imports `dex_index` (to drop an index row when retention deletes its dex — `dex_index` does not import `service`, so no cycle); `artifacts` stays pure; `analysis` and `capstone` stay pure; `memory` depends on `service` + `capstone`; `syscall_watch` depends on `service` + `analysis`. No circular refs.

## Why the split (was: one 1585-line `index.ts`)

Adding a crypto hook once meant reading the whole file; the REST surface was inline `if(pathname===)` blocks. State, service, MCP, and the three HTTP route domains are now separate, while `router.ts` preserves one ordered table and one matching implementation.

## Adding a new capability

- **MCP tool**: add one `{ name, description, inputSchema, handler }` to `MCP_TOOLS` in `mcp.ts`. Handler calls `agentCmd`/`dumpBuf`/`dumpRegion`/… from `service.ts`. Done — `tools/list` + `tools/call` pick it up automatically.
- **REST route**: add one table entry to the owning `http/routes_*.ts` domain. Preserve domain composition order in `http/router.ts` when paths overlap.
- **Agent command op**: handled in the agent C `command_loop` (Phase 3 — table-driven after refactor).
- **CLI subcommand**: add one entry to `COMMANDS` in `cli.ts` (its own flags + `handlerFlags`). Two guards
  then apply automatically: `test/cli_args.test.ts` fails if a declared flag is not in `handlerFlags`, and
  `tools/verify_v100_adh_cli.sh` fails unless every declared flag has an observable effect. Never add a
  flag to the shared set "for later" — an accepted-but-ignored flag is how this kind of tool lies.

## Known flake (pre-existing, in `service.ts` reconstructSo path)

`verify_v08_disasm`/`verify_v08_analyze` intermittently report `exports=0` on the memory-reconstructed `.so`: `readMem` breaks early on a short first chunk (`service.ts` `readMem`), truncating a PT_LOAD and dropping the dynamic segment. Passes on re-run. Fix candidate: read each PT_LOAD segment boundary precisely rather than assuming contiguous.

### backends.ts (module W)

Shared injection-backend matrix: ackendMatrix() (sessions by entry, host-side Frida Gadget cache, device-side backend pointers) and classifySession() (which paths are really loaded in one target, from the agent's own maps). Used by REST GET /api/backends AND the MCP tool ackends — one implementation, two surfaces.
