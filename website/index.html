它只在运行时
说出真话。

ADH 把一枚轻量 agent 注入你勾选的 Android 应用。密钥、方法与内存从运行时读出来；索引、反汇编和数据库都留在电脑上。

加固防的是磁盘，
不是运行时。

抽壳、字符串加密、控制流混淆，说的是同一句话：别在磁盘上读我。可程序总要跑起来，密钥要展开，明文要进出，方法要执行。

ADH 不试着把加壳的程序静态读懂。它只把一支很小的 agent 放进进程，钩住该钩的地方，把发生的事转述出来。索引、反汇编、数据库，都留在你的电脑上。

目标进程不该因为被看着，就变慢、变胖、变得好认。

在进程里，能看见什么

六族能力，逐包开关。关掉的族在目标进程里根本不装钩子，不是记录时再过滤。

crypto

加解密现场

注入后观察 Cipher、Mac、MessageDigest 与 Signature 的 init、doFinal、digest、sign、verify。原方法照常执行，记录里带算法、操作、密钥、IV、输入与输出。

AES/CBCAES/GCMRSAHmacSHA256SHA-256

hook

方法与调用

Java 方法可改参数、换返回值、跳过原函数，也可一次装全类。JNI 覆盖 RegisterNatives 与 JNIEnv 表；native 覆盖 GOT、inline、调用点与函数指针槽。

LSPlantDobby16 槽

trace

指令与系统调用

函数参数、线程、时间戳；QBDI 指令级 trace；直接 svc #0 的捕获，以及 libc 站点的静态归因。只装命中的站点，不铺满整个进程。

QBDIsvclibc

memory

内存与活体对象

搜索、读取、导出、写回；活体对象字段读写；硬件写观察点回答「谁写了这块缓冲」，给出真正执行写入的那条指令。

DEX 与 so

枚举、dump、按 SHA-256 去重，标出诱饵壳与真代码；修复、重建、读方法字节码。电脑侧建索引、搜索、xref、反汇编。

给分析程序的门

浏览器只读查看采集结果；MCP 让分析程序直接提问。adh CLI 把 Host 转成 stdio，客户端不接触 HTTP 端点。

四层，各做各的

重的东西不放进目标进程。这不是优化，是设计前提。

  1. 01

    送进去

    Zygisk 从 memfd 把 .so 送进目标进程，目标 maps 里不出现模块路径。只注入勾选的包。

  2. 02

    只看与转述

    agent 约 1 MB，只做钩、读、转述。没有网页，没有数据库，没有反汇编。

  3. 03

    在电脑上分析

    Host ADH Daemon 接收、落盘、建索引、反汇编，提供 HTTP 与 MCP。

  4. 04

    你来提问

    浏览器只读；分析程序走 adh mcp，拿到同一批事实。

一次加密，七个字段

算法、密钥、IV、明文、密文在同一行里。要复算，不必再猜。同一套字段也用在 Mac、MessageDigest 与 Signature 上。

凡例

工具的边界写在明处，省得你在错的地方找答案。

设备
一台已 root 并开启 Zygisk 的手机，KernelSU 或 Magisk 均可。正式支持的 ABI 只有 arm64-v8a。
作用域
只注入勾选的包，主进程与 :core 一类子进程一起。没勾选的应用不会被碰。
密钥
密钥放在 Android Keystore 里时，getEncoded() 为空，记录里的密钥字段就是空的。
分片
update() 分片再空参收尾的，输出在、输入不在；写进调用方自己缓冲区的重载，反过来。
缺口
wrap 与 unwrap、密钥协商、PBKDF2 与 HKDF 没有钩；应用自己实现的算法、直接走 libcrypto 的路径，也不在这四个接口里。
观察点
硬件写观察点在 SELinux Enforcing 的 app 域会被内核拒绝，需要 permissive 才能布防。
槽位
单目标最多 16 个并发 hook 槽，超出直接报错，不静默丢事件。
网络
Web 与 MCP 默认 8088，agent 用 8761。两个端口都没有登录验证，并且监听所有网卡，只在你信得过的网络里开。

从这里开始

一条命令一条命令地走。从源码构建需要 Android SDK、NDK 28.2.13676358 与 Node 24。

  1. 01

    刷入

    bash tools/build_bundle.sh
bash tools/flash_device.sh --reboot

    也可以在 root 管理器里选「从本地安装」，装 injector/zygisk/dist/ 下的 bundle zip，然后重启。

  2. 02

    勾选

    打开 ADH Manager，在「注入范围」里勾选应用，需要的话再调该应用的 Hook 配置，保存。重新打开目标应用。

  3. 03

    连上

    bash tools/dev_up.sh

    它会启动 Host ADH Daemon 并设好 adb reverse。浏览器打开 http://<局域网地址>:8088/<包名>。

  4. 04

    接 AI

    pip install android-decrypt-hub
adh connect 127.0.0.1:8088
adh mcp

    客户端只认 adh mcp 转出来的 stdio，不直接接触 HTTP 端点。

需要什么

  • 已 root、开启 Zygisk 的手机，arm64-v8a
  • 一台能跑 Node 24 的电脑
  • adb，以及手机与电脑之间的连接
  • 只在你拥有或获得授权分析的应用上使用
