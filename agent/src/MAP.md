# Agent source map

`libadh_agent.so` stays collect/execute-only. HTTP, MCP, storage, indexing, and heavy analysis belong to the Host ADH Daemon.

## Layout

| Path | Responsibility |
|---|---|
| `bootstrap/agent_main.c` | Dual entry, first-loaded-copy owner guard, late reporter binding, hello/report, command dispatch, and lifecycle. Also sends the `caps` frame right after the hello: `ADH_AGENT_OPS` + the limits (`hookSlots`/`memWindows`/`writeMax`/`frameMax`), which the daemon's `capabilities` tool serves verbatim. That array and the `strcmp(op, …)` dispatch are two hand-written lists, so `daemon/test/agent_caps.test.ts` parses both and fails when they differ. |
| `bootstrap/agent_internal.h` | Shared bootstrap utility, transport, memory, and filesystem declarations |
| `bootstrap/util.c` | JSON, base64, property, process, and time helpers |
| `bootstrap/io.c` | Host connection and length-framed transport |
| `bootstrap/mem.c` | Maps, memory read, magic scan, byte search, and **write**. `cmd_write` is the deliberate host-driven patch path: 1..4096 bytes, refuses an unmapped address or a range leaving its mapping, refuses a non-writable page unless `force:true` (then mprotects, restores the original protection immediately, flushes the I-cache for code pages) and returns the replaced bytes so the host can undo. `adh_mem_region_of` is the one "what is at this address" query; `adh_mem_write_checked` is the never-faulting copy the native-hook hit path uses. `parse_mem_addr` accepts `0x…` and bare hex and refuses a partial parse. |
| `bootstrap/mem_read.c` | The one memory-read backend. `/proc/self/mem` when the target allows it, otherwise a bounds-checked direct copy inside a short signal guard (a target that makes itself non-dumpable makes `open("/proc/self/mem")` fail with EACCES even for itself, which used to kill read/search/scan/dump/art_dexfiles together). Owns the fd — released at the end of each command so no standing `/proc/self/mem` descriptor is left in the target — and reports which route answered (`adh_mem_backend_name`). A target that refuses the fd cannot be produced on demand, so `mem_backend` can FORCE the direct route session-wide: `adh_mem_fd()` then answers -1 and every call site (read / search / scan_magic / art.c / trace) takes the direct branch with no per-site change, which is how the fallback gets covered for commands other than `read`. Nothing else in the agent may open `/proc/self/mem` |
| `bootstrap/fs.c` | Directory listing and file-read commands |
| `capture/capture.c` | Crypto/TLS/file/system wrappers, bounded capture buffers, Java reporter, and the capture command family (`capture_start`/`capture_stop`/`capture_drain`) + `file_probe`/`got_enum` recon. TLS records carry the `SSL*` as `conn` so the host can pair HTTP/1.1; the agent does not reassemble HTTP. The one-shot probe commands that hardcoded a target trigger (`crypto_hook_test`, `net_hook_test`, `file_hook_test`, `flow_watch`, `detect_watch`, `inline_crypto_test`, `crypto_probe`) were deleted on 2026-10-01 — the persistent capture set + the caller-side trigger replaced them. Holds the **per-package hook policy** (`adh_capture_set_families`, set by the Zygisk companion before `adh_agent_start`) and applies it inside every install: a family the policy turned off is never installed and is reported in the reply's `skipped`. Nothing here arms itself — the caller names the module, the policy only decides which families of that install survive. System hooks are observe-only on each comma-separated name in `sysModule` (at most 8): `ptrace`, `access`, `faccessat`, `__system_property_get`, `__system_property_read_callback`. Each line carries the return value and the caller `lr`; the host classifies them. |
| `hook/got.c` (self-identity) | `adh_self_module_name()` derives our own module name from `dladdr` instead of hardcoding `libadh_agent.so` (GOT self-test / stealth pool own-GOT lookup / footprint counter keep working when the agent is loaded from a memfd). `adh_self_image_bounds()`/`adh_image_bounds_of()` give our image's address range (min/max PT_LOAD): our own mappings are recognised by *address*, because a memfd agent's name (`jit-cache`) is also ART's JIT-cache name. `adh_self_build_id()`/`adh_build_id_of()`/`adh_build_id_from_phdr()` read the GNU build ID out of PT_NOTE in memory - the exact identity for "another copy of this same .so", used by the single-instance guard so a coincidental span match on an unrelated module can no longer suppress the agent (span stays as the no-build-ID fallback) |
| `hook/got.c` | ELF relocation parsing, GOT slot replacement, in-memory symbol lookup, and GOT self-test |
| `hook/slot_hooks.c` | Pointer-slot ("vtable") backend (covers object vcalls: vptr -> RELRO table -> `ldr/ldr/blr`, and writable callback pointers with `slotsWritable`): rewrites 8-byte DATA slots that hold the target address (virtual dispatch tables, callback tables, GOT entries) so indirect calls are intercepted with zero code changes; scans readable non-exec ranges by scope, labels each slot `got` (GLOB_DAT/JUMP_SLOT relocation) or `data`, reuses the verified thunk emitter (no BL-range limit for a pointer call) and the RELRO-safe pointer swap, and restores every slot bit-exactly on unhook |
| `hook/site_hooks.c` | Call-site ("sites") backend: rewrites the `B`/`BL` call sites that reach a function (own module by default, other modules with `scope`; one level of PLT/tail-call resolution) to hand-encoded arm64 thunks on per-site memfd pages within ±128 MB, so the target entry stays byte-identical. Matching the original instruction form (`b` vs `bl`) is required, every emitted thunk is self-checked before installation, and the patch is fully reversible (own patcher, no Dobby state) |
| `hook/stealth_pool.c` | Opt-in trampoline-pool camouflage for authorized anti-detection work: swaps this module's own RELRO GOT slot for `mmap`, so Dobby's arenas land in a `memfd:jit-cache` mapping instead of an anonymous executable page (thread-local redirect window around the Dobby calls, always falls back to the real `mmap`, reports its errno honestly) |
| `hook/native_inline_dobby.cpp` | Dobby native inline-hook backend |
| `hook/native_hooks.cpp` | Unified native hook registry (status carries MECHANISM, not just counters: for `mode=got` it reports `slot`/`slotsPatched`/`slotCurrent`/`pageProtRestored`+`pagePermsBefore/Now`/`installedAtMs`/`firstHitMs` and a `verdict` of `fired` vs `installed-never-fired`, because address/target/original are all the same pre-patch slot VALUE and `hits:0` used to be ambiguous between "never fired" and "no traffic"): GOT/inline/address install (prologue snapshot + patch verification), arm64 register-capture stubs, NATIVE_HOOK events (x0-x8/x18 + x29/x30, and with `backtrace:true` the caller chain captured AT THE HIT by walking the thread x29 chain inside its own stack bounds). Optional `mem` windows (`auto`, or `x0:64` / `x0+16:32`, x0–x8, ≤4 × ≤192 bytes, ≤512 total) are copied on the hit thread with `process_vm_readv` BEFORE the original runs and emitted as `NATIVE_HOOK_MEM` paired by `seq`. `auto` keeps readable pointer arguments at 64 bytes and skips integers. A bad pointer on an explicit window is `unreadable`, throttled hits are not copied. Soft unhook by default and opt-in hard unhook (writes the saved original bytes back, frees the slot, leaves the Dobby pool untouched). Optional `writeReg`/`writeOff`/`writeHex`: at the hit, before the original runs and before any register rewrite, the bytes are copied into `*(xN + off)` through `adh_mem_write_checked` — only inside an already-writable mapping, so a bad pointer can never fault the target. This is what makes an out-parameter check failable (`__system_property_get(name, buf)`, a caller-supplied key buffer) without patching code; every event carries `write:{reg,offset,len,ok}` and status carries the spec (`x0+0:8`). Optional `errno`: written on the hit thread on every hit (throttled included) so a check that branches on the return/errno PAIR can be neutralized — meaningful with `skipOriginal:true`, because a running original overwrites errno with its own result. Verified on device: `Os.access("/nope")` reports `ENOENT` before the hook and `EACCES` after `returnValue:-1, errno:13`. **Post-call capture (`memAfter`)**: an ordinary hook's stub TAIL-JUMPS to the original, so nothing of ours can run after it returns; a hook that asks for `memAfter` is installed with a different stub (`adh_native_stub_after_N`) that CALLS the original, copies ONE window (1..512 bytes, `x0:256` / `x2+16:32`) into a NATIVE_HOOK_MEM record tagged `phase:"after"` plus the return value, then hands the value back untouched (q0-q3 are saved across the callback so float/vector returns survive). It is the only way to see what a function WROTE - a compressor output, a decrypted plaintext, a PRG keystream. Verified on device: `compress` + `memAfter:"x0:320"` yields `78 9c …`, and that buffer inflates back to the exact 371-byte fingerprint JSON. Optional `traceInsns`/`traceFrom` run an in-hook QBDI trace at the hit and write it into the SAME event under `trace` (no companion record; absent when off, and refused with skipOriginal/returnSet because a trace executes the original). |
| hook/java_lsplant.cpp (hook_all) | `action=hook_all` installs every method of a class in one call (optional name/params filters, "*" = any): it collects declared + inherited members (keyed on name AND params, so foo(int)/bar(int) both land), installs each through the ordinary single-hook path, and returns hookIds plus the matched count so a slot-limited batch is visible |
| hook/java_lsplant.cpp | LSPlant v6.4 ART hook shim (optional static link over the same Dobby backend): methods incl. inherited ones (superclass-chain resolution, declaring class reported) and constructors (`method: "<init>"`, ctor-argument observation, skip/override rejected). `stack:true` makes `AdhJavaHookBridge` capture a bounded caller chain at the hit (app frames only, plumbing filtered) that every JAVA_HOOK event and the per-hook status report. **Argument rendering lives in the Java bridge, not here**: `agent/java/com/adh/agent/AdhJavaHookBridge.java` renders ALL arguments (receiver excluded) and type-aware - `byte[]` as a 64-byte hex head plus the true length, `URI`/`URL`/`CharSequence` and `Map`/`Collection`/`org.json` as `toString`, primitive arrays expanded - because protocol analysis needs the values, and `java.net.URI@30d92b0` is not one. Single-argument calls keep the historical bare-value form. Editing that file requires regenerating the embedded dex (`tools/build_java_hook_bridge.sh`, or javac + d8 + the header generator on a machine without bash) and rebuilding the agent |
| `runtime/actions.c` | Safety-gated Java trigger, explicit in-process `.so` loading, and the typed `native_call` active-call command (integer/pointer args in x0-x7, `f:`/`d:` args in s0-s7/d0-d7) |
| `runtime/fp_call.S` | AAPCS64 trampoline for `native_call`: loads x0-x7 from the integer bank and d0-d7 from the FP bank, calls the target and writes the d0 return through the caller's out-pointer (a per-call slot, not a global, so concurrent calls cannot cross). Must stay assembly: a naked C version loses the argument registers under -O3, and x3 has to be parked because it is caller-saved |
| `runtime/art.c` | ClassLoader-cookie enumeration and per-API ART DexFile structural resolution |
| `runtime/inspection.c` | Live-object reflection, JNI/runtime compatibility probes, and the bootstrap/current injection-footprint counters |
| `runtime/java_enum.cpp` | Live-class reflection: enumerate class metadata/constructors/overloaded methods/fields and actively invoke static or field-backed instance methods. **Argument marshalling covers arrays**: a JSON array for a `T[]` parameter becomes an object array element-by-element (type name accepted both as `java.lang.Object[]` and as the `[Ljava.lang.Object;` descriptor `Class.getName()` returns), and a JSON string for a `byte[]` parameter becomes its UTF-8 bytes — without this a dispatcher such as `main(int, Object[])` cannot be called at all. **A `byte[]` INSIDE an `Object[]` needs the explicit wrapper** `{"$bytes":"<utf8>"}` or `{"$bytesHex":"<hex>"}`: array elements are typed by the declared component (`Object`), so without it the dispatcher receives a String and aborts the VM on `GetArrayLength`. The call result renders arrays element-wise (a `String[]` used to come back as `[Ljava.lang.String;@1a2b3c`). Reflection failures unwrap `InvocationTargetException` to its **cause** before reporting (`android.system.ErrnoException: access failed: EACCES (Permission denied)`), because the wrapper's own name tells the caller nothing it can act on. **Detached calls** live here too: `adh_java_call_async_start/_status/_list` run the same invocation on their own attached thread (detached pthread, JVM detached on completion) and keep the last 16 jobs, so a method that blocks parks one thread instead of the command channel — the synchronous path cannot survive a target that waits for its own worker thread. |
| `runtime/jni.c` | JavaVM discovery, native-thread attach/detach, and app ClassLoader access. The VM is normally handed over by `JNI_OnLoad`; when it is not (a real injected target, where the agent is mapped from a memfd and the linker refuses `dlopen("libart.so")` for namespace `"(default)"`), `JNI_GetCreatedJavaVMs` is taken out of the already-loaded libart.so by in-memory symbol lookup, with dlopen only as a last resort |
| `runtime/jni_hooks.c` | Global JNIEnv->RegisterNatives hook and bounded JNI_NATIVE registration events |
| `runtime/jni_env_hooks.c` | JNIEnv function-table per-entry hooks: the thirteen fixed entries (member IDs, byte-array read + in-place writeback, primitive-array critical pair) plus every Call*Method / NewObject family and all three JNI forms (varargs / V / A) — 76 slots total — with resolved member labels, rendered arguments, wildcard install ("*" / prefix*), ABI-guarded slot offsets, bounded JNI_ENV events and a per-slot `last` snapshot with bounded JNI_ENV events, reactivation and clean slot restore |
| `runtime/jni_method_names.c` | jmethodID -> "<class>#<name><signature>" resolution for the Call* hooks (reflection over the receiver chain, mid-keyed cache, capped scans) |
| `runtime/jni_onload.c` | JNI_OnLoad work: already-loaded module discovery, inline hook with prologue snapshot, manual invocation, real unhook (restores the bytes), plus the load-time watch state consumed by `runtime/dlopen_watch.c` (skip/return replacement of a load-time call) |
| `runtime/dlopen_watch.c` | Lazily-installed dlopen watch on **both** entry points (`dlopen` and `android_dlopen_ext`/`__loader_` alias, each with its own trampoline). Two consumers: the JNI_OnLoad watch (patch a module's entry before the VM calls it) and the opt-in **`module_watch`** broadcast, which emits a `MODULE_LOAD` capture event (path, handle, base, size) for every library mapped afterwards — the initial map of an already-loaded module never passes here, a runtime-decrypted payload does. Hooking only the first entry that resolved made the broadcast blind to plain-`dlopen` loads (including the agent's own `load_so`), which is what the two slots fix. |
| `trace/commands.c` | QBDI command response handling (`qbdi_trace`). The one-shot function tracer (`trace_run`) was deleted on 2026-10-01: `native_hook mode=got` + `java_call` + `native_backtrace`/`trace_digest` cover it without hardcoding a target trigger |
| `trace/qbdi_trace.c` | QBDI instruction trace, two entry points over ONE run engine and one set of guards. `adh_qbdi_trace` = standalone command-thread trace (`qbdi_call`, library loaded/unloaded per call). `adh_qbdi_run_from` / `_ex` = **in-hook** trace from an arbitrary pc with the hit's registers (`gpr` = x0-x8, x29, x30, x18), used by `native_hook { traceInsns, traceFrom }` on the TARGET thread: **per-thread VM** (`pthread_getspecific`, never a global lock), 300 ms wall clock, instruction budget, executable-range snapshot, `pc == lr` return detection, thread-local re-entrancy guard. The range snapshot is immutable once published and replaced by a pointer swap (in-hook runs read it concurrently); it is rebuilt only when the start address is not covered. An inline hook's entry carries our own Dobby branch, so that path starts in the trampoline and adds its page + the function's module explicitly (`qbdi_addInstrumentedRange`), otherwise the run reports `did-not-run`. `stopReason` is the caller's fact: `completed | instruction-budget | time-budget | ran-away | left-range | did-not-run | reentrant`. Costs (documented in `qbdi_trace.h`): the traced function EXECUTES under the emulator (twice per hit), stack-passed/float arguments are not seeded, and libQBDI.so must be loadable in the target (a real app usually needs it pushed + `load_library` first). Optional **write watch** for the run (`traceWatch: "x0:32"`, same window grammar as `mem`, armed as `qbdi_addMemRangeCB(QBDI_MEMORY_WRITE)` and deleted right after): the event then carries `traceWatch {lo, hi, count, truncated, hits:[{pc, insn, addr, size, value}]}`, i.e. WHICH instruction wrote WHICH address with WHICH value — the software stand-in for a hardware watchpoint, which app domains are denied (perf_event_open: errno 13) |

## Naming

`libadh_agent.so` is the single shipped agent name; the exported entry point is `adh_agent_start`. New code, commands, logs, and UI copy use `ADH` / `adh_*`. The fixed `com.idh.probe` / `IDH_PROBE_OK` fixture is intentionally hash-bound.

## Phase 3 extraction rule

Move one capability domain at a time and preserve command names and response schemas. A new module exposes a narrow header, is added to `agent/CMakeLists.txt`, and must pass `tools/build_agent.sh` plus its focused acceptance script before the next domain moves.

Phase 3 domain extraction is complete. Further bootstrap work should focus on table-driven RPC dispatch, not moving isolated helper functions solely to reduce line count.

## Versioning

`AGENT_VER` in `bootstrap/agent_internal.h` must equal `version` in `injector/zygisk/module/module.prop`:
the module ships this `.so`, so "which agent is flashed" and "which module is flashed" cannot have two
different answers. It is reported by `compat_probe` (and in the hello) so a session can be checked against
the build you think you flashed. Both the module zip and the agent must be rebuilt/reflashed together.

## Release footprint

- `tools/build_agent.sh` keeps `libadh_agent.so.debug` locally and stages only a stripped `.so`.
- `exports.map` restricts `.dynsym` to `JNI_OnLoad`, `adh_agent_set_package`, `adh_agent_set_policy`, and `adh_agent_start`.
- `compat_probe` reports bootstrap vs current exec/anon-exec/RWX counters; base injection and GOT hooks must not add true anonymous executable pages.
