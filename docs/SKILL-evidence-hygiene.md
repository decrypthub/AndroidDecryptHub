# Skill: 逆向证据卫生（Evidence Hygiene）

> 这个 Skill 解决另一类反复出现的失败：**观察本身没错，但从观察推到结论的那一步错了。**
> 以下每一条都对应一次真实的误判，不是理论风险。

## 一、变量必须先做敏感度扫描，再谈"是否参与"

**错法**：测了 3 个变体，都让输出变了 → 断言"这个输入的全部字节都参与"。

**实际踩的坑**：某个 8 字节输入，改了前 5 字节输出全变，于是断定"64 位全部参与"。
后来逐字节扫一遍才发现：**只有前 5 字节有效，后 3 字节完全被忽略。**
此前基于"完整 8 字节"做的所有搜索都落在错误的输入空间里。

**正确做法**：

```
对输入的每一个字节位置：
  翻转该字节（^0xFF），比较输出
  不变 → 该字节不参与
  变了 → 该字节参与
```

不要抽样。**边界只能靠逐字节扫出来。**

## 二、样本归一化必须动态推导参数

**错法**：在进程 A 测出"剥离时用掩码 0xC0"，就把它硬编码进脚本。

**实际踩的坑**：进程 A 是 `0xC0`，进程 B 是 `0x40`，进程 C 是 `0x80`。
硬编码导致其他进程的样本全是脏数据，所有基于它们的搜索都无效。

**正确做法**：

```
1. 取同一输入连续调用两次，得到变体 X 和 Y
2. 差异位置 = { i | X[i] != Y[i] }
3. 掩码 = X[18] ^ Y[18]（任选一个差异位置）
4. 归一化 = 把高变体按掩码 XOR 到低变体
5. 用 8 组以上输入验证归一化后完全一致
```

**验证通过才算归一化正确。** 不要跳过第 5 步。

## 三、"代码存在"不等于"代码执行"

**错法**：静态反汇编找到一段完整的算术实现，就认为找到了算法。

**实际踩的坑**：找到 `add/sub/mul/div/mod/and/orr/eor/lsl/asr/lsr` 全套实现，写了详细分析。
后来在同一轮里下断点对照才发现：**那段代码在整个调用中 0 命中。**

**正确做法**：任何静态发现的代码，**必须用同轮对照断点验证是否执行**。

```
对照组：一个已知必然命中的地址
实验组：候选地址
同一轮、同一配置、同一触发
对照组命中而实验组 0 命中 → 候选与本次分析无关
```

## 四、统计口径要穷尽，不要抽样

**错法**：抽查 20 条指令，没看到乘法混合 → 断言"没有乘法混合"。

**正确做法**：

```
全镜像所有 mul：逐条分类（(x-1)*x 谓词 / idx*4 寻址 / 其他）
可达指令集合：从实际执行的入口出发，按深度展开，统计 op 直方图
```

**抽样能证伪，不能证真。** "没看到"不等于"没有"。

## 五、绝对地址 vs 模块偏移

**错法**：反汇编里 `bl #0x6f9b54ba28`，直接把 `0x54ba28` 当偏移去查。

**实际踩的坑**：正确偏移是 `0x6f9b54ba28 - 0x6f9b510000 = 0x3ba28`。
用错偏移会断到 +4MB 外的地址，永远 0 命中。这个错误出现了 5 次。

**正确做法**：先算 `地址 - 模块基址`，再查反汇编表。

## 六、运行时地址每次重新获取

**错法**：把 `state 指针`、`VM 基址`、`TID` 写死在脚本里。

**实际踩的坑**：目标进程重启后全部失效。曾据此读出乱码，还误判成"地址失效"。

**正确做法**：

```
每次采样前：
  memory_maps        → VM 基址
  android.os.Process.myTid → TID
  断点读 x0          → state 指针
```

## 七、单样本不下结论

上面 1、2、3、4 的共同根因都是**单样本/单次观察**。

**规则**：任何"规律"至少需要：
- 3 个不同的输入
- 2 次重复验证
- 1 次边界测试

三者缺一，结论标"待复核"，不能写进交付物。

## 八、报告里必须区分"已验证"与"推测"

```markdown
✅ 实测：8 组 payload × 2 次调用，8/8 一致
⚠️ 推测：可能是 XX 构造（未验证）
❌ 已否证：YY 方案（96 种组合 0 命中）
```

**不要把推测写成实测。** 也不要把"没测到"写成"不存在"。

## 一句话

**观察是廉价的，从观察推到结论是昂贵的。** 每次下结论前问：
「这个结论如果错了，会是什么样子？我测过那个样子吗？」
