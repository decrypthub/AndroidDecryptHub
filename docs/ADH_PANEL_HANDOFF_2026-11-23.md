## 2. 用户要的产品，不是一次演示

电脑 CLI 提供网关和网页；一个网关能切换多台手机。手机侧管理服务、APP 进程里的采集组件、手机管理界面不是同一层。**USB/局域网连通、选中 APP、配置已保存、配置已生效、收到了日志，是五件不同的事。**

1. 先选设备，标明 USB / 局域网。列当前设备已安装的 APP，不要求 APP 已启动或有日志。切换 APP 只改变查看对象，不自动打开注入、不启动或重启进程。
2. 用户希望列表能按 APP 设置“允许注入”；进入 APP 后再设范围、功能和具体 Hook。配置至少按设备和 APP 隔离；切换进程或会话不能把旧数据带过来。只有手机确认保存才能显示“已保存”，只有运行回报才能显示“已生效”。
3. 设置参考 IDH 和用户给的 iOS 原型：保留配色，左侧分区，右侧按类别分组；组头是选项的“已选/总数”，不是记录数。算法可逐个勾选，展开显示类、方法，并区分预设与实际收到的回报。设置不放流水，暂不显示任务或 AI 动作，不要删掉用户已有的 MCP 入口。
4. 系统页是事件时间线，文件读写属于系统筛选；左栏只列事件，搜索和筛选放在页签同行右侧。文件页是浏览器：左侧目录、右侧内容；可写时明确保存位置。不重复堆设备名、包名、大标题或日志跳转。读取失败不是空目录。算法输入输出需要 Base64（来自实际字节），它是需求，不是本交接已验证的结果。
5. dump 是独立页。用户要的是选中会话后发起一次操作，看到**本次**产物；旧产物列表不等于该功能已完成。网页面板、手机端和 MCP 是不同入口，不要默认为每个入口都有相同权限。
