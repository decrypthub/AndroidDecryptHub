# ADH 工作台：功能与数据边界

ADH 是连接设备的 Android 运行时分析网关。工作台的顺序是**选设备 → 选 APP → 查看对应会话**。选择查看对象不等于修改手机上的分析范围；APP 加入范围、设备配置保存、配置在运行会话中生效是不同状态。同包名在不同设备上是不同对象，归属未核验的旧会话不能按包名拼到任意设备。

| 页签 | 要回答的问题 | 数据来源 |
| --- | --- | --- |
| 加解密 | 当前会话执行过哪些加解密操作？ | 实际上报的记录。能确认的算法、类和方法照实显示，缺失的不补猜。 |
| 系统 | 应用采集了哪些设备指纹、做过哪些环境探测、读写哪些文件？ | 顶部指纹摘要按信号去重并带采到的值；下方是系统调用与文件读写事件时间线，可按活动类型筛选。文件事件描述一次操作，不是目录索引。 |
| 网络 | 当前会话观察到了哪些网络活动？ | 已上报的网络记录。组不成完整请求时，不把碎片当成完整请求。 |
| 文件 | 选定设备上的这个 APP **现在有哪些文件**？ | 当前 APP 的授权目录和文件内容。目录浏览不依赖任何文件事件。 |
| dump | 当前会话有哪些已登记的运行时产物？ | 与 APP 和会话绑定的产物及其来源。不是文件目录，也不是日志导出。 |

## 记录列表的计数与翻页

记录页脚固定显示「共 N 条 · 第 k 页 · 状态」。N 是当前设备、APP、类别与筛选条件下在**保留窗口**内命中的条数，不是当前页的条数；翻页按页向更早读取，一直能翻到保留窗口最旧的一条。保留窗口之外（每包上限，默认 5000 条）与采集期被丢弃的记录确实不再可读，提示里直接写明丢弃数，不能用一个总数暗示「全部都在这里」。单页条数由「N 条/页」选择器控制（默认 300），只影响一页显示多少，不影响总量。

## 文件与系统的分界

- **系统是设备指纹观测 + 行为时间线。** 顶部指纹摘要回答「应用采了什么」：android_id / IMEI / MAC 等标识符与型号、属性、包列表等设备信息，按信号去重并带采到的值；下方事件时间线（系统调用 + 文件读写）是证据链——文件读本身就是指纹采集通道（/sys 网卡地址、/proc/cpuinfo），两者对照看才完整。反分析检测（反调试、root、签名、模拟器、完整性）仍在后台分类，取证用 detect_summary。
- **文件是现状。** 有授权的目录来源时，左侧浏览目录及名称、大小和修改时间，右侧显示点击的文件内容。查看范围以顶栏为准，文件页不重复设备或 APP 信息，不放事件入口。有没有文件读写事件不影响目录浏览。只读入口可以另存完整预览文本到电脑，不能写回手机；独立文件入口仅在显式授权时才允许写回相应文本。
- **空目录必须来自一次成功的目录读取。** 离线、设备或 APP 归属未核验、连接未提供目录读取、读取被拒绝是不同状态。不能把「未上报读写事件」当成「目录为空」。切换页签不自动启动设备动作。
- 原 USB 观测入口保持自有调试 APP 的只读 `files` 目录。独立文件入口使用所选自有调试 APP 的 UID，只接受它自己的沙盒和应用专属外部目录，不监听 Agent、不依赖观测会话、不改 USB 转发。外部目录受 Android 实际权限约束，失败显示原因而不是空目录；不扩展到其他 APP 或整机路径。
- 文件验收使用同一自有 Demo 的 `fileLab` 隔离构建（`com.adh.sandbox.filelab`），不替换正在采集的 Demo。专属外部目录由应用通过 Android 的 `getExternalFilesDir()` 打开；调试接口仅向 USB 调试 shell 开放，不随常规包发布。不自动生成数据；手机上的验收文件由显式的 `prepare` 操作创建且不覆盖已有内容。开启 `ADH_OWN_EXTERNAL_DEMO=1` 后该入口默认显示实际外部目录；再开启 `ADH_OWN_EXTERNAL_EDIT=1` 才能将 `adh-demo-external.txt`（UTF-8/LF，最多 8 KiB）写回原文件，其它文件仍只读。
- 独立文件入口可显式授权沙盒 `files` 下一个已存在的 UTF-8/LF 文本；页面「保存到手机」核对版本后写回原路径。未授权、截断或二进制文件不可编辑；「另存文本到电脑」仍是另一回事。
- USB 面板的 dump 页可以对已注入并连上的 APP 进程发起内存读取，同时列出已经登记的产物。进程没有连上时只说明未连接，不把旧产物当成这次读取。

## 设置

只显示配置、作用范围和必要的生效说明；实际记录条数、命中数、最近事件和产物统计留在各自的记录页。设置组头的「已选 / 总数」只数开关选项，不数事件。

- **分析范围**说明选定的设备、APP 和观测会话；真正修改范围须与查看选择区分。顶栏 APP 菜单只负责选择，PID、在线与离线会话明细放在设置的「分析范围」。
- **功能和 Hook 状态**区分期望配置、已保存、已生效和未上报。功能详情只按面板当前在线会话归集已加载的事件入口，展开显示实报的类、方法或参考标签；旧会话和归属不明的记录不计入。同一功能可有事件但没有入口字段。设备没有上报预设或安装回执时明确标为未知，不用事件补成安装清单。
- **API 采集开关**和「记录显示」是两个功能。前者只显示当前设备和 APP 声明、且当前入口授权的采集点。页面发送选项 ID 和旧版本，收到手机回执再显示生效；拒绝、断开或版本不符时不猜测状态。
- 当前实机入口给自有 `apiLab` Demo：`MessageDigest.digest(byte[])` 与 `CRC32.update(byte[])` 在 Demo 调用点逐项记录，开关存入该 APP，两个 API 依旧正常执行。列出应用的 USB 入口只在选中这个 APP 时使用同一手机回执；选中其他 APP 时不发送这些设置，也不写入注入范围。此验收使用限定操作的 USB 调试通道，不开放任意类、方法、地址及通用 Agent 指令；不替换原 Demo 或文件验收版。
- **记录显示**只筛选已采集的记录，不写回手机。关闭显示类别保留逐算法、逐 Hook 的选择；回到同一个查看范围才读取其偏好。人和 AI 使用同一授权范围，禁用或未授权的能力不由另一个入口绕开。

## 连接与数据

顶栏「设备」与下拉列表标明 USB 或局域网，依据当前核验的连接，而非上次记录或 APP 是否上报。ADB 网络连接与直连 USB 分开显示；读取失败或旧服务未区分时显示「连接情况未知」，不冒充离线。USB 已连接时，APP 仍可能在等待 Agent 会话，两者在「连接与数据」分行。

设备管理是一个独立窗口（点顶栏「设备」打开），不是下拉菜单：左侧按「全部 / 已连接 / 未连接」分组，右侧是当前选中设备的名片、连接事实与操作，下方是该组设备列表。给设备起显示名、设为默认、记住暂时没插的设备、忘记，都在这个窗口里完成；添加设备也在窗口内展开，可选已插上的 USB 串号或无线调试地址（`adb connect`，host:port），网络地址添加失败时保留真实原因（拒绝连接、超时），不把地址登记成一台在线设备。显示名、默认与「记住」只存在当前浏览器（localStorage），权威连接状态一律来自 daemon；daemon 重启或换数据目录不会让已记住的设备从列表里消失，但也不会伪造「在线」；多标签同时打开时写入按磁盘合并，不互相覆盖。忘记只从面板列表移除，不断开手机、不改手机上的设置。

「重连」按层返回结果，不是一句 succeeded：ADB 链路（手机在不在、是否未授权）→ agent 反向隧道（缺失时补，不动已有映射）→ 设备域 `adh.device/1` 通道 → 观察设备的 agent 强制重拨。观察设备以 agent 回到在线判成功，其它设备以设备域通道判成功；某一层没通时把原因写进结果，不用别的层的成功掩盖。全部重连只覆盖已记住的设备，不会顺手连到列表里只是「可发现」的手机。

USB 和局域网是设备到电脑的连接，MCP 是客户端到电脑的接口。此页分别展示已核验的设备连接、电脑健康检查以及 MCP 客户端未核验/当前入口未开放；不把健康检查成功报告成 MCP 已接通。刷新只读，不建立会话。需要更换查看对象时回到已有的设备选择器。

选定的本地 APP 与采集连接分别显示。USB 面板用手机上的 root 守护程序列出并读取所选 APP 自己的沙盒，不依赖采集会话，也不扩展到其他 APP 或整机路径。自有 `com.adh.sandbox` 仍可走显式授权的 `files` 目录。文件读取不开启注入。

USB 面板可显式开启当前 Android 用户的已安装包清单。清单与采集会话无关；包名以手机包管理器为准，选择别的 APP 不继承 Demo 的文件或采集权限。
